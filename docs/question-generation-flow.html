How Pulse Med writes your questions

From the topic you type to the finished test. Numbers in the green boxes are from a real run: "Lung carcinoma", 100 questions.

Step 1 · You type a topic

The database is searched first

In"Lung carcinoma", exam, count (100)
OutA list of database topics, each with a tier and a PYQ score
  • Words that mean the same are matched together: cancer, carcinoma, tumour, malignancy.
  • All 19 specialties are searched, not just one. The biggest specialty is kept to about 14 topics; every other specialty with matches gets a few places.
  • If you ticked chapters in a specialty instead, each ticked name is looked up in the database (the whole name and its parts).
Real run: 20 database topics: Pathology 14, Surgery 3, Medicine 2, Radiodiagnosis 1.
Code: lookupTopicsBalanced in chapterTopics.ts, splitTopic in ai.ts
Step 2 · Backup list

The AI proposes its own subtopics, held in reserve

One model call, helped by a web and book search, splits the topic into subtopics. With 6 or more database topics, these are kept apart as "extra" and used only if the database cannot fill the count. With fewer, they are merged in after the database topics. The prompt asks for subtopics from every specialty that examines the topic, with none taking more than a third.

Code: /api/ai/split-topic in server.ts
Step 3 · Facts, not topics

Every question starts from one quoted fact

InEach subtopic, searched in your books (and the web if books are not the only source)
OutA fact plan: one fact per future question, with the exact quote and its source
  • The model lists distinct, exam-testable facts. The quote must appear word for word in the source, or the fact is dropped.
  • Web facts are filtered: case reports, study statistics, hedged statements and formulation science are removed. Books are trusted.
  • Repeated facts are removed (word match, then one model pass).
  • Facts that an earlier saved question already tests are skipped, so old questions do not come back.
  • No specialty may take more than about a third of the plan.
  • If the database facts fall short of the count, the reserve subtopics from Step 2 are searched outside, and those facts are added.
  • The plan is kept for 24 hours per topic and count.
Real run: 85 facts planned: Pathology 34, Medicine 3, Surgery 1, Radiodiagnosis 1, and 46 from outside the database (Pharmacology, Community Medicine, Surgery, Medicine).
Code: planTopicFacts, dedupePlan in ai.ts; builder in PracticeModuleBuilderView.tsx
Step 4 · The count

You get what the sources support

The number of planned facts is the number of questions. If you asked for 100 and 81 facts exist, you get 81 and a note says so. Nothing is padded.

Real run: asked 100, note said "Only about 81 relevant questions are available".
Step 5 · One slot per fact

Style, closing question and difficulty are decided

  • Style: one-liner, short case, vignette, NOT-true item, image, calculation, mechanism, match-the-following (INI-CET only), mixed in the exam's own proportions.
  • Closing question: diagnosis, finding, next step, drug of choice and so on. For a Pharmacology topic, diagnosis and investigation are removed, so the question is about the drug.
  • Difficulty: about 20% easy, 45% medium, 35% hard.
  • Facts are ordered so that topics asked more often in the papers get more slots.
Code: planSlots in questionStyles.ts, weightedOrder in ai.ts
Step 6 · The prompt for one question

What the writing model is told

  • It is a senior NEET-PG / INI-CET item writer. Plain patient or exam situations only: no study, audit or "a resident proposes" wording.
  • The exam's own pattern (options, marking, style mix).
  • The subtopic, the planned fact and its exact quote. The question must test that fact without giving it away.
  • How the exam asks that topic: ChatGPT's note from the PYQ research for this topic.
  • The style and closing-question rules for this slot.
  • For Pharmacology: the answer must be a drug, mechanism, adverse effect, interaction, dose or antidote, never a diagnosis or organism.
  • What is already in the set: patients, drugs, answers and key facts to avoid repeating.

Up to 20 questions are written at the same time (your parallel limit). Each returns one JSON question with options, key, explanation and key fact.

Code: GENERATOR_SYSTEM, the prompt array in generateExamQuestions, ai.ts
Step 7 · Checks

A question that fails any check is thrown away and rewritten

Shape: stem too thin, wrong closing question, bad option set
Repeats: same patient, same answer or same fact as one already kept
Wording: research, audit or resident-review language; animal or veterinary cases
Subject: Pharmacology item asking for a diagnosis, disease or organism
Source: the key must be supported (web sources are re-checked; books are trusted)
Examiner: a second model call rejects a wrong key, two defensible answers, out-of-scope or non-exam items

Passing questions get a repaired explanation if it does not say why each other option is wrong, the correct letter is rotated across A to D, and a picture is planned when the fact has a typical image.

A failed slot is rewritten, or filled from a spare fact. If the set is still short, up to 60 further rounds run until the target is met.

Real run: 6 rounds, 0 questions permanently dropped, 81 of 81 kept.
Step 8 · Optional

Image questions

If images are on, a slice of the set is built from curated bank pictures. The question is written from the picture and then verified. A question that fails is dropped, and the text questions remain.

Step 9 · Opening the test

Saved, de-duplicated, opened

  • Every batch is refined, saved to the question bank and QA-checked while the next batch is still being written.
  • A last duplicate check removes any question whose wording is 60% or more like a stored one.
  • The set is stored as a saved question bank, and the test runner opens. Your answers, flags and position are saved per bank, so you can leave and return.
Code: launchWith in the builder; handleLaunchModule in App.tsx; moduleStore.ts
Result
